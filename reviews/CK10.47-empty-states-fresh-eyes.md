# CK10.47 — todos' empty list and the folder browser's folder with no folders, read cold in both appearances

## What was reviewed

Headless renders at one pixel per point, light and dark: the whole Todos
window (650×600 under a 32 px title-bar strip) with no todo, at both "Show
scroll bars" settings; and vaultview's Open Vault dialog over its window with
the folder browser showing a folder whose listing holds no folder. The
reader saw no source and no packet, was given the Empty state entry of
DOMAIN.md and the full text of reviews/misreads.md, and was asked what a
developer who uses macOS every day would complain about in how each empty
state is drawn.

## The reviewer's reply, verbatim

I found no defect against the Empty state ruling in either empty state. Position, size and colour all match it to within 1 to 2 px. The only complaints I'd file are about wording, plus one judgement call on the empty scroll-bar lane at Always.

**Todos (650x600 window)**

1. **Horizontal placement is correct in both settings.**
   - WhenScrolling: the ink of "No todos." runs x 266–383, so its centre is 324.5. The window centre is 325.
   - Always: the ink runs x 261–378, so its centre is 319.5. The centre of 0–640 is 320, so the 10 px lane is left out as the ruling asks. The text shifts exactly 5 px.
2. **Vertical placement is correct.** The ink runs y 288–308 and the string has no descenders, so its centre is about 298.5. The centre of the full frame, title-bar strip included, is 300. The centre of the content below the strip alone would be 316, and the text is not there. That is the "toolbar's share included" rule, as in Mail.
3. **The colour is exactly the tertiary label colour.**
   - Light: (189,189,189) on (255,255,255), which is black at 26% over white.
   - Dark: (86,86,86) on (30,30,30), which is white at 25% over #1e1e1e.
4. **The size is large, Mail-style.** The cap height of the "N" is 20 px (y 289–308). That is about 28 px Roboto, which suits a whole column standing empty. I can't check it against the stored measured value from the pixels alone.
5. **Wording (minor).** A Mac developer would want "No To-Dos" or "No to-dos", in the style of Mail's "No Message Selected". "todos" isn't how platform apps spell it, and the platform's line has no trailing period. Capitalisation could be a harness substitution, but the spelling and the period are the app's own choices.
6. **The scroll-bar lane at Always is a judgement call.** The lane reserves 10 px but draws nothing: the pixels at x 635 and 645 (y 300) are the plain background, (255,255,255) light and (30,30,30) dark. A list view whose scroll bars hide when the content fits gives the content the full width. So the text sits 5 px left of the visible centre with nothing on screen to explain why. The ruling's "a standing scroll bar's lane" decides which way is right. Either the lane is standing and should show its track, or nothing is standing and the text should centre at 325.
7. **The blue add button is not part of the empty state.** It is a Material-style corner button at x 594–633, y 544–583. It stays in the corner rather than standing under the line as a centred action group. The ruling makes actions optional ("may"), so this is not an empty-state violation. A Mac developer would still object to the button itself.

**Folder browser ("Open Vault" dialog, light and dark)**

8. **Horizontal placement is correct.** The ink of "This folder holds no folders." runs x 451–648, so its centre is 549–549.5. The dialog spans x 270–830, so its centre is 550.
9. **Vertical placement fits the list region.** The ink runs y 400–411, so its centre is 405.5. The path trail's ink ends at y 291 and the footer separator is at y 515. The list region between them centres at 403 if it starts right under the trail, or about 407 if it starts with some padding. Either way the text is within 2–3 px. The text stays in the list and does not centre over the whole dialog, which spans y 219–581 with its centre at 400. That is correct for a field inside a sheet.
10. **The size is the row size.** The cap height of the "T" is 11 px (y 401–411); the "M" of "Macintosh HD" in the path trail is 10 px (y 279–288). That difference is within the 1 px tolerance for font metrics, so the line is at the size of the rows it stands for.
11. **The colour is tertiary in both schemes:** (189,189,189) on 255, and (86,86,86) on 30.
12. **Wording (minor).** "This folder holds no folders." says "folder" twice and ends in a period. A Mac developer would write "No Folders" or "No subfolders".

**Verdicts**
- **Todos:** it meets the ruling. My only reservations are the wording ("todos" and the period) and the invisible 10 px lane at Always.
- **Folder browser:** it meets the ruling. The only complaint is the clumsy wording that says "folder" twice.

## Disposition

No defect against the Empty state entry. Item 6, the standing lane drawn with no track, is finding 1137, planned as CK10.43. Item 7, the add button, is the application's own composition; its overlap with the last row is finding 1153, planned as CK10.48. The folder browser's line says the folder holds no folders because the task states that sentence. The closing period, items 5 and 12, is filed as finding 1171.
